## 3. Objective Hardware Limitations & Waiver Declarations

In compliance with [docs/en/TESTING_CHECKLIST.md](file:///docs/en/TESTING_CHECKLIST.md), boundary tests restricted by physical hardware or external network conditions are formally waived and documented below:

1. **Multi-Carrier Physical 4G/5G Cellular Base Station Roaming (Dimension 3.3)**:
   - **Limitation**: Testing was performed over fixed broadband and public cloud links without a dedicated programmable cellular SIM test rig.
   - **Compensating Control**: Full coverage provided via Linux kernel `tc qdisc add dev lo root netem loss 30% delay 150ms 20ms` chaos injection and automated in-place `ice_restart: true` re-negotiation.
2. **Apple WebKit Native Engine Testbed (Dimension 4.6.2)**:
   - **Limitation**: Testbed nodes consist of Windows 11 and Linux Debian 13; physical Apple macOS/iOS hardware was unavailable.
   - **Compensating Control**: Modern Chromium and Edge dual-engine testbeds strictly asserted W3C standard compliance (`new Response(null, {status: 204})`, Module Workers, Streams API).
3. **Pure Single-Stack IPv6-Only Cellular NAT64 Environment (Dimension 3.5)**:
   - **Limitation**: Dedicated IPv6-only cellular network with upstream DNS64/NAT64 translation was unavailable.
   - **Compensating Control**: Dual-stack and IPv4 fallback paths verified via STUN/TURN degradation matrices and local candidate gathering unit tests.
