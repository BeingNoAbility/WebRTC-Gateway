# 故障排查与常见问题 (Troubleshooting & FAQ)

---

## 1. 常见故障排查手册

### ① 页面一直卡在“正在连接 Agent (Connecting)”或最终报 ICE 连接失败
- **故障根因**：双方网络存在最严格的**对称型 NAT (Symmetric NAT / NAT 4)**，导致纯 STUN 反射候选无法完成打洞；
- **排查与解决**：
  1. 打开右下角 WebRTC HUD 悬浮球，查看 ICE Candidates 候选列表；
  2. 若两端都是对称型 NAT，必须配置 TURN 中继服务器以实现平滑降级：
     ```bash
     ./agent -node-id myhome \
             -target http://127.0.0.1:8080 \
             -turn-url turn:relay.yourdomain.com:3478 \
             -turn-user your_username \
             -turn-pass your_password
     ```
  3. 配置 TURN 后，系统将自动使用 `relay` 候选在中继模式下完成直连，HUD 状态药丸将切换为 `🛡️ TURN Relay`。

---

### ② 局域网纯 IP 访问时 Service Worker 注册失败或页面白屏
- **故障根因**：现代浏览器安全规范（W3C Secure Context）强制要求：**Service Worker 仅允许在 `localhost` 或具备有效 SSL/TLS 证书的 `https://` 域下激活**。在局域网直接用纯 HTTP 打开 `http://192.168.1.100:8888` 会被浏览器直接拦截 Service Worker；
- **一键解法**：
  在启动一体化信令服务端时增加 `-tls-auto` 参数：
  ```bash
  ./signal -addr :8888 -tls-auto
  ```
  服务端将在内存中动态签发覆盖本机所有局域网真实物理网卡 IP 的 ECDSA SAN 证书。在浏览器直接打开 `https://<局域网IP>:8888/#myhome` 接受证书提示，即可完整激活 Service Worker！

---

### ③ 移动设备（手机/笔记本）在 Wi-Fi 与 5G 移动蜂窝网络间切换时连接断开
- **自动自愈机制**：
  系统原生内建了**双阶段 WebRTC ICE Restart 韧性流水线**：
  1. 手机切网瞬间底层 TCP/WebSocket 套接字断开，浏览器自动闪连信令并保留原有 PeerConnection；
  2. 触发带有 `iceRestart: true` 的新一轮 Offer 协商；
  3. Agent 具备 5 秒断网宽限保护期，取消提前析构，在新网络建立后无缝继续传输数据；
- **排查提示**：若漫游自愈偶尔失效，点击右下角 HUD 诊断看板中的 **`🔄 立即触发 ICE Restart`** 按钮可一键手工自愈。

---

### ④ Docker 容器内的 Agent 无法访问宿主机的 `http://127.0.0.1:8080`
- **故障根因**：Docker 容器默认处于独立的 Bridge 网络命名空间中，容器内的 `127.0.0.1` 指向容器自身而非宿主机；
- **推荐解法**：
  - **Linux 宿主机**：在 `docker-compose.yml` 或 `docker run` 中添加 `network_mode: "host"`（或 `--net=host`），Agent 直接共享宿主机网络栈，访问 `127.0.0.1` 畅通无阻；
  - **Windows / macOS Docker Desktop**：将 `-target` 设置为 `http://host.docker.internal:8080`。

---

### ⑤ 提示 401 Unauthorized 或“信令集群准入拒绝”
- **故障根因**：密钥配置缺失或不匹配；
- **排查清单**：
  1. **检查控制面集群密钥**：确认信令服务端的 `-signal-secret` 与 Agent 启动时的 `-signal-secret` 完全一致；
  2. **检查数据面访客口令**：若 Agent 配置了 `-access-secret`，访客必须在弹窗中输入该口令，或使用对应的 HMAC-SHA256 签名分享链接（`#nodeId?exp=xxx&sign=yyy`）；
  3. **参数语义规范**：请确认使用语义明确的 `-signal-secret`（集群注册）与 `-access-secret`（访客口令），旧版 `-secret` 别名已不再支持。

---

### ⑥ 浏览器控制台报错：WebSocket 连接失败 (403 Forbidden) 或 CSWSH 跨域阻断
- **故障根因**：信令服务端默认启用严格同源检查（Strict Same-Origin Only），强化防御跨站 WebSocket 劫持（CSWSH）。当浏览器 Web 门户的前端地址（`Origin` 标头，如 `https://portal.yourdomain.com`、`https://*.pages.dev` 或本地开发端口 `http://localhost:5173`）与信令服务端的对外域名或端口不一致时，跨域 WebSocket 握手将被服务端直接拦截并返回 `HTTP 403 Forbidden`；
- **排查与解决**：
  1. **配置允许的 Origin 白名单（生产环境推荐）**：
     在启动信令服务端时添加 `-allowed-origins` 参数，或配置环境变量 `SIGNAL_ALLOWED_ORIGINS`（支持逗号分隔、子域通配符 `*.pages.dev` 与端口通配符 `localhost:*`，支持域名与端口解耦匹配）：
     ```bash
     ./bin/signal_linux_amd64 -addr :443 \
       -allowed-origins "https://*.pages.dev,https://portal.yourdomain.com,http://localhost:*"
     ```
  2. **临时放行所有跨域握手（仅限测试/开发环境）**：
     在本地调试或独立内网环境中，可传入 `--allow-all-origins` 参数（或环境变量 `SIGNAL_ALLOW_ALL_ORIGINS=true` / `ALLOW_ALL_ORIGINS=true`）关闭白名单校验；
  3. **命令行 Agent 检查**：Go CLI Agent 与 curl 等原生命令行客户端不发送浏览器 `Origin` 请求头，不受此策略阻断，直接基于 `SIGNAL_SECRET` 与 HMAC 签名鉴权。

## 2. 常见问题 (FAQ)

### Q: 访问内网服务时，访问者的手机或电脑需要额外安装软件或插件吗？
**A:** 完全不需要。访问者只需使用任何现代主流浏览器（如 Chrome、Edge、Safari、Firefox 等），直接打开 Web 门户地址或分享链接即可直接访问内网服务。无需在访问端安装客户端应用、无需配置 VPN 虚拟专网，也无需在浏览器中安装扩展插件，真正实现“零客户端依赖”。

### Q: 使用该工具需要被访问端具备公网 IP 或配置路由器端口映射 (DDNS) 吗？
**A:** 完全不需要。系统底层基于标准的 WebRTC 点对点（P2P）通信协议，能够在双方设备之间自动发起网络打洞并建立直连数据通道。即便你的家庭宽带处于运营商大内网（多层 NAT 架构）、没有固定公网 IPv4 地址，或者租住房屋无法修改路由器配置，只要通过极低配置的轻量信令服务协助交换握手信息，两端设备即可自动穿透完成直连。

### Q: 数据传输安全吗？我的私有数据会不会被云端服务器或第三方窃听？
**A:** 具备极高安全性。通信链路具有以下安全保障机制：
1. **传输层强制加密**：所有经由 WebRTC 传输的数据，底层强制采用 DTLS 1.2 与 SRTP 密码学协议进行端到端加密，任何第三方均无法窃听明文；
2. **直连不经过云端**：打洞成功后，数据直接在两端设备间点对点传输，公网信令服务器完全不触碰、不中转任何业务数据帧；即便在极少数打洞失败而启用 TURN 中继的情况下，中继服务器也仅转发加密的数据包，无法解密传输内容；
3. **严格鉴权与防重放**：系统支持访客口令验证以及基于 HMAC-SHA256 与设备证书指纹绑定的时效分享链接，即便分享链接不慎泄露给其他人，也可有效抵御跨设备的非法使用。

### Q: 如果我通过它下载 NAS 里的几十 GB 电影或大文件，会消耗我的公网服务器流量吗？
**A:** 在绝大多数网络环境下完全不会。
- 当两端成功建立 P2P 直连通道后，数据流量完全经由双方本地宽带之间的物理链路直接传输，网络速度由两端的实际上行与下行带宽决定，**不经过公网云服务器，消耗的云服务器流量为 0**；
- 只有在双方设备均处于极其严格的企业防火墙或对称型 NAT 且无法直连时，系统才会自动切换为通过 TURN 服务器中继传输，此时才会使用中继服务器的流量。

### Q: 苹果设备（iPhone / iPad / Mac Safari）和安卓手机都能正常使用吗？
**A:** 均能良好兼容使用。只要操作系统的浏览器内核满足主流规范（如 iOS 14.3+ 上的 Safari、Android 8.0+ 上的各类现代浏览器），即可顺畅打开。移动端支持完整的触控操作、多媒体音视频在线流畅播放、长按操作以及大文件直接保存到本地。

### Q: 手机在外使用时，从家中 Wi-Fi 切换到 5G 蜂窝网络，正在访问的页面会断开吗？
**A:** 不会中断。系统内建了智能网络自愈机制（ICE Restart）。当手机检测到底层网络从 Wi-Fi 漫游切换为 5G（或在不同 Wi-Fi 之间切换）时，后台会在不断开当前网页、不重新加载页面的前提下，自动在几秒内重新协商网络路径并恢复数据通道，视频播放与网页操作将自动顺畅继续。

### Q: 我能同时通过它连接家里的多台电脑或多个不同服务（如 NAS 面板、Jellyfin、相册等）吗？
**A:** 可以，管理非常灵活：
- **多服务独立节点**：你可以在不同电脑或同一台机器上启动多个 Agent，并赋予不同的名称（例如 `nas`、`jellyfin`、`photos`）；
- **子域名物理隔离（推荐）**：支持使用泛域名解析（如 `nas.p2p.yourdomain.com` 与 `jellyfin.p2p.yourdomain.com`），不仅简单直观，而且浏览器会为每个应用划分完全独立的登录 Cookie 与本地存储，多服务同时登录互不冲突；
- **单域名访问**：也可以通过统一门户加上标识符（如 `https://p2p.yourdomain.com/#nas`）实现即开即用。

### Q: 如何将家中电脑里的某个大文件安全临时分享给朋友？
**A:** 非常简单快捷，省去先上传到第三方网盘的漫长等待：
1. 在电脑上以单文件模式启动 Agent，并指定允许访问的时长（例如 24 小时）：
   ```bash
   ./agent -file ./family-video.mp4 -access-secret mypass -sign-link 24h
   ```
2. 终端会直接生成一条带时效签名的专用访问链接；
3. 将链接发给朋友，朋友在电脑或手机浏览器打开后，即可直接从你的电脑以满速 P2P 传输下载（支持断点续传）。24 小时一到链接自动失效，无需手动清理或关闭。

### Q: 屏幕右下角经常出现的悬浮小药丸是什么？如果挡住了页面内容该怎么处理？
**A:** 悬浮药丸（Smart Pill）是网页内置的轻量交互助手，显示当前的连接状态、网络延迟以及提供重连或调试控制台。如果你觉得它影响视觉或操作：
- **一键极简折叠**：点击药丸上的折叠按钮，它会立即缩小为一个仅 28 像素的半透明呼吸小微点；
- **自由拖拽与边缘吸附**：你可以用鼠标或手指拖动它到屏幕任意不碍事的位置，松手后它会自动吸附到屏幕边缘；
- **零按键干扰**：悬浮药丸完全不会拦截你的键盘按键。当你在使用网页版终端（如 Web SSH）、在编辑器写代码或填写长表单时，所有快捷键与输入都能直接送达底层应用。

### Q: 为什么有时候页面一直停留在“正在连接”或提示连接失败？普通使用者应该如何排查？
**A:** 如果遇到连接不上，建议按以下顺序快速自查：
1. **确认目标电脑/NAS 是否开机且 Agent 在运行**：检查家中电脑是否进入了休眠状态、是否断网，或者 Agent 终端窗口是否被意外关闭；
2. **确认访问口令是否正确**：如果目标节点设置了访问密码，请核对弹窗中输入的口令是否一致；如果使用的是朋友发来的分享链接，检查链接是否已经超过了有效期限；
3. **检查两端网络环境是否过于封闭**：如果访问者处于公司严苛的企业局域网中，直连可能会被企业防火墙策略阻挡。此时只要在 Agent 或服务端配置好免费的 TURN 中继，即可顺利恢复连通；
4. **尝试手动重连**：点击右下角悬浮药丸，在弹出的面板中点击“重连”或“触发 ICE Restart”，通常可快速恢复正常状态。

### Q: 是否提供图形化桌面客户端 (GUI)？
**A:** 本项目核心专注于轻量无状态的命令行守护进程（Agent CLI）与免装客户端的浏览器 Web 门户。对于桌面图形界面需求，社区提供了快速搭建的原型客户端 [WebRTC-Gateway-GUI](https://github.com/BeingNoAbility/WebRTC-Gateway-GUI)。需注意该 GUI 为独立实验性项目，未经充分测试验证，不在本项目的核心管理与支持范围内。
